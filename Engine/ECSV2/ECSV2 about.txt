General Work Flow:

Creating an entity:
Each entity is Created in ECSV2scene's constructor
Each entity is a collection of components
Add the appropriate components (these can be actual data or just tag components) and all done

Animation:
Animation Components are essentially just data needed to access an animation from an AnimationRepository

You can tell AnimationSystem to make either set the next Animation of an entity, or force the current animation to change

Sprites:
Sprites are 1 frame animations,

Inputs:
Event based inputs.
Components (either data based of state based components) will subscribe to the event system and input a function (SO far only implementation for keyboard call backs have been made),
the function which is typically declared in the components will give a function which modifies their own members to an event system, which then is checked and processed by a system given 
some components and their members.




NOTE:

The more I think of components having the ability to update, the less I agree with such aspects, since systems are not always using mutually exclusive components
there can be overlap in which components are being used multiple time, and then you have an arbitrary way of updating components.
In order to prevent this arbitrary choice, and only updating on first go, you'll then need the components to be even more complex having data on whether they've been updated this instance or not,
which I don't think is a great path for futher development
